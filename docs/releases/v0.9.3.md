# SQUAD 0.9.3

This release is about closing the gaps that a review of 0.9.2 found in the
gates themselves. Nothing in the mission protocol changed shape; several things
that were documented now actually hold.

## The approval gate is real

`squad_plan` (submit, get, approve, reject) and `squad_mission` now call
`permission.assert`. Before this, any agent holding the squad tools could
approve its own plan and skip the human step that the `/squad` command asks
for. A denied permission leaves the mission in `plan_gate` with nothing hired.

## The reviewer sees the whole change

`staff.worktree_base` (migration 010) records the commit each worktree branched
from, and the diff is `git diff <base>`. A worker that makes three commits is
reviewed on all three, not only the last one. Rows created before 0.9.3 fall
back to `HEAD^`.

## Integration is all-or-nothing

`squad_integrate` records the main HEAD before a batch. If a later cherry-pick
conflicts, main is rewound to that commit, every task merged by this call is
unmarked (`integration.rollback`) and the worktrees are kept for a retry.
Worktrees are removed only after the whole batch lands. A half-integrated
mission can no longer look finished.

## Helper sessions are released

The reviewer, the second reviewer, the process auditor and the arbiter are
interrupted and removed once their verdict or ruling is recorded. Cost and
tokens stay in the ledger; the sessions do not pile up.

## Configuration is live

`SquadStore` accepts a `SquadConfig`. `maxRework` drives escalation,
`hardLimitUsd` blocks new assignments once a mission is over budget
(`budget.hard_limit`), and `softWarnPct` sets the budget radar thresholds.

## Smaller fixes

- `hasAudit` counts `second_review` audits only, so a task legitimately named
  `mission` is no longer shadowed by the process audit row.
- `squad_tasks` reports `mission_status`, `readiness` and `needs_attention`
  with the failed, escalated and cancelled tasks.
- The `squad-reviewer` agent follows the class-appropriate check list instead
  of demanding `diff + tests` for every class.
- Assignment uses a conditional `UPDATE` and fails loudly if the task moved.
