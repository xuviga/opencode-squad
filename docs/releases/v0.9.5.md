# SQUAD 0.9.5

The allowlist stops being advice.

## Scope is enforced, not described

In 0.9.4 a task could declare `paths` and the reviewer was told which files it
owned. That fixed false failures, but a worker could still change anything and
the reviewer had to notice.

Now `squad_wait` checks the worker's own diff before the report is accepted: in
a worktree mission, any changed file outside `paths` fails the task with the
event `task.scope_violation`, listing the files and the allowlist. No reviewer
is hired, no tokens are spent on a review that cannot pass.

## Where it does not hold, and why

`isolation: "none"` takes a folder-wide snapshot, so a changed file cannot be
attributed to one worker — a sibling task may have written it. The allowlist
stays advisory there: the reviewer partitions the diff and is told which files
are sibling work. Making the same guarantee hold without git needs per-task
file locks or a pre-report ownership check; that is the next item in the
roadmap, not a claim in this release.

## Also

- `squad.tuiState()` now carries `metrics` next to the budget, so a panel can
  show pass@1, rework, failures and cost per integrated task without extra
  calls.
- 117 tests. `tests/reliability.test.ts` covers `scopeViolations` on a mixed
  diff.
