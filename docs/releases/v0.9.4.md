# SQUAD 0.9.4

This release comes from a live mission that failed in three places. Each failure
is now a test.

## The database survives a plugin reload

The host disposes and reloads plugins while tool calls may still be running —
`session.move` triggers it, and so does any plugin reload. Closing the SQLite
handle on dispose made those calls fail with `Cannot use a closed database`, and
four workers finished with nothing captured.

The plugin now opens **one handle per project directory** and never closes it on
dispose. A reload reuses the same connection; the process closes it at exit.
`tests/reliability.test.ts` proves a released handle stays usable.

## A worktree mission is checked before it exists

`isolation.worktreeAvailable` only means "this folder is a git repository". The
host can still refuse to create a worktree — a stale worktree registry is one
known cause — and the failure appeared only at the first `squad_hire`, with an
empty error message.

`squad_mission create` with `isolation:"worktree"` now creates and removes a
throwaway worktree first. If the host cannot do it, the mission is not created
and the error names the cause and the two ways forward. `squad_status` reports
`isolation.worktreeUsable` next to `worktreeAvailable`.

## Scope belongs to the task, not to the folder

In `isolation:"none"` every task sees a folder-wide snapshot diff. A reviewer
failed a task for files that belonged to its siblings — a false fail that cost a
rework.

A task can now declare `paths` in the plan or pass them to `squad_assign`:
exact files, `docs/` prefixes or globs such as `src/**/*.ts` (migration 011).
The reviewer and the auditor partition the diff, are told which files this task
owns, and are told explicitly that out-of-scope changes are sibling work. The
allowlist scopes the review; it does not yet block a write — that is issue #3.

## Metrics that can be reproduced

`squad_report` now prints and returns pass@1, rework rate, failure rate,
disputes, audits and cost per integrated task, all computed from task rows and
the ledger. No dashboard, no estimates.

## Also

- README gains a "Why SQUAD" section with the three observed problems and the
  mechanisms that answer them, plus a plain paragraph on what the project does
  not do.
- `docs/POSITIONING.md` states who the project is for, who it is not for, and
  how it differs from CodeRabbit, Superset/Paradev and agent-of-empires.
- `package.json` description is one sentence under 120 characters.
