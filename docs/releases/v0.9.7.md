# SQUAD 0.9.7

The last field that was documented but inert now moves the machine.

## A blocked worker looks blocked

`report.status` was validated, stored, and ignored. A worker that returned
`blocked` looked exactly like one that finished, so a reviewer was hired to
judge a deliverable that did not exist.

`squad_check` now applies the report:

- `blocked` → task `blocked`. No review, no rework attempt spent; the block is
  the worker saying "I need a decision", not a failure.
- `failed` → task `failed`, so the existing `maxRework` gate and escalation
  apply.
- `done` → the old path to `submitted`.

A blocked task is re-issued with `squad_assign`; the worker prompt says the
block did not cost an attempt, and `squad_tasks` counts it in
`needs_attention`.

## Why `blocked` is not `returned`

`returned` means the reviewer judged the work insufficient and the worker must
redo it — that is a rework. `blocked` means the task cannot proceed without a
human: a missing credential, an ambiguous requirement, a dead dependency.
Treating them the same punished the worker for the environment.
